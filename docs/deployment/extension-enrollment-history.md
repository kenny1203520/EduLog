# EduLog 0.1.0：完整歷史同步（1000126）

本文件說明目前版本。先前 1000122–1000125 文件保留作為舊工作與部署紀錄；本版將已確認的教學原文與來源位置保存到伺服器 enrollment 歷史，不再只保存在瀏覽器。

## 部署

1. 備份資料庫，依既有流程套用前置 migration 至 1000125，再新增 **1000126_enrollment_history_reports.sql**。沒有修改任何已部署 migration。SQL 以交易執行；側載 ZIP 不會自動執行 SQL。
2. 同時部署本次 API 與主站程式碼，重新啟動 API。保留精確的 `API_EXTENSION_ALLOWED_ORIGINS`，並將 `EDULOG_WEB_BASE_URL` 設為可開啟的前端網址，包括自訂端口與路徑前綴。
3. 解壓 `EduLog-Teaching-Tools-0.1.0-complete-history-sync.zip`，在 Chrome／Edge 更新原有未封裝擴充套件。先保存原站草稿，再刷新來源分頁。
4. 在 popup 重新檢查連線；`GET /api/extension/v1/me` 的 workspace 能力須包含 `enrollment_history_reports`、`per_occurrence_report_routing`。manifest 維持 **0.1.0**。

舊伺服器阻擋新的歷史同步並提供升級說明；舊匯入工作仍可使用原批次、冪等鍵與檢查點續傳。舊工作未提供 `report_session_ids` 時維持單班次限制。新版可帶最多 50 個已確認的報告目的班次；每個目的班次仍執行權限檢查。

## 老師的操作流程

- **讀取與核對：**預設讀取目前班級各報名全部可讀歷史，也可縮小日期範圍。重新同步掃描完整索引，沒有可靠更新版本的編輯頁重新讀取。名單與報告列表依報名／報告身份合併，完整編輯頁補齊允許欄位。
- **處理例外：**有效身份記憶收合為摘要。歷史分為「可綁定課次」「先存歷史」「需要處理」，可搜尋及篩選。無日期、日期矛盾、同日身份不足、未知教材或多個合法課次提供具體問題；逐筆重試、明確略過及先存歷史可繼續其餘資料。
- **摘要並同步：**查看學生、報名、歷史與目的課次摘要後一次確認。新建對象與非空欄位覆寫仍須明確確認；內部紀錄另行選取。再次同步仍保留摘要確認，沒有新資料時不建立新伺服器工作。
- **結果：**分開顯示新增、更新、無變更、保留原值、歷史保存與課次綁定結果。已保存歷史不是未匯入；待處理／略過造成部分完成。結果提供「處理未完成項目」，原工作與已提交批次保持不變，重新讀取與核對建立獨立後續工作。

### 單次調課

學生與課程相符的已確認報名可保留原班次。班次差異只代表需要逐堂核對，不清除對應，也不建立第二筆報名。

例如 10/03 → 10/04：10/04 報告僅在有效調課目標、實際課次日期、有效名單與權限都符合時綁定；10/03 與其他日期分別核對。取消、被後續調課取代或已取消課次不適用。來源課次日期可在所選目標日期區間外；報告仍須在本次日期範圍內。

不建立調課、不搬移既有報告、不改寫 enrollment 的學生、課程或班次。沒有唯一合法課次時只保存 enrollment 歷史。尚未建立的報名先同批建立並保存歷史，再由主站依實際名單核對綁定。

## 伺服器資料與介面

`enrollment_history_reports` 獨立保存日期、允許教學欄位、來源身份狀態、來源原文、位置證據、版本與已綁定報告 ID。無報告 ID／編輯連結時使用 `evidence_only`；內容去重識別與正式來源 ID 分開，同日內容變更／多筆需人工核對。可靠來源 `/edit` 網址保存為報告連結。

歷史不建立虛構課次，不計入名單、出席統計或未填報告。主站學生報告與報名報告頁可檢視及綁定；綁定後原報告出現在既有課次報告區，歷史清單／助手不重複列出。助手將未綁定歷史當成明確選取的範本，保留學生／日期差異確認；不建立錯誤身份記憶，不自動勾選原站確認欄或送出。

| 擴充套件 API | 用途 |
| --- | --- |
| `GET /api/extension/v1/history-reports` | 指定學生或 enrollment 的權限篩選清單；游標分頁，最多 50 筆；支援課程、來源報名、日期與最近日期排序 |
| `GET /api/extension/v1/history-reports/:id` | 可讀歷史詳情與版本 |
| `POST /api/extension/v1/history-reports/route` | 對 enrollment 的最多 50 個日期核對合法課次與目前報告；游標分頁 |
| `GET /api/extension/v1/history-reports/:id/candidates` | 該歷史日期可綁定的合法課次 |
| `POST /api/extension/v1/history-reports/:id/bind/preview` | 鎖定來源／目標版本，預覽逐欄差異 |
| `POST /api/extension/v1/history-reports/:id/bind/apply` | 使用相同 key 與內容，交易內套用及保存關聯 |
| 既有匯入 preview／apply／complete | 新增 `history_report` 類型，仍最多 50 筆及既有大小限制；分類結果與完成核驗沿用 |

背景程序持有憑證；API 固定呼叫受限的歷史 RPC。主站透過已允許的 `enrollment_history_access` 使用登入使用者身份。歷史讀写依實際 enrollment 的教學報告範圍，綁定另檢查目標課次、原生報告建立／更新權限、生命週期與有效名單。

綁定 preview 與 apply 的 enrollment、歷史、課次及報告快照必須一致。回應中斷保留原冪等鍵與請求核對；不以新鍵盲目重送。歷史與課次報告的關聯同交易提交，失敗一同回滾。已綁定來源內容改變時列為待核對，不直接覆寫。

名單依實際綁定的班次／課次日期核對。來源歷史只能證明當日已有讀取報告的學生，無法證明整班完整名單；畫面明示來源名單不足，不把其他學生當成應移除的資料。

## 資料保留與回復

只保存允許的教學欄位與路徑／表格／列／擷取時間證據。沒有整份 HTML、頁面腳本、登入值、地址、證件、薪資或行政個資。內部紀錄預設不保存／不套用，需老師另行勾選。

本機原文、草稿、讀取檢查點沿用受信任 IndexedDB、實例／使用者隔離與七天期限，完成或取消清除來源內容；部分完成保留修正所需檢查點。已確認同步的歷史是伺服器持久資料，沒有七天自動清除；取消工作不撤回已寫入資料。

部署回退時先停用新版同步入口，保留 1000126 表與已提交結果；不要刪除歷史資料或重寫既有批次。依備份与專案資料庫回復流程處理，不直接撤回 migration。驗收與尚未實測項目見 `extension/tests/ACCEPTANCE-1000126.md`。
