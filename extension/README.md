# EduLog Teaching Systems extension

## Clear theme and connection management (0.1.0)

The interface style is **EduLog 清晰主題** (EduLog Clear theme). Use **套用清晰主題** to apply it and **使用原站主題** to return to the supported website's style. It remains available without pairing.

The popup and site integration panel open a dedicated workspace for **教學資料匯入**, **報告預填**, and **工作紀錄**. After pairing and installing migrations 1000118–1000122, current-class import, enrollment reconciliation, effective-roster verification and report prefill are available. The workspace shows the source site/class and destination instance. UI styling still works without pairing; extraction starts only after the user requests it.

Before running this API version, apply migrations through **1000122** in order (including **1000116**, **1000117**, and **1000118**), restart the API and reload the unpacked extension. Save drafts before refreshing existing source tabs, then recheck the connection. The manifest remains **0.1.0**. Existing paired tokens can be adopted when that browser rechecks its connection; other unidentified legacy rows remain intact. The workspace requires `catalog_v1`, `multi_course_import` and `mapping_memory`; student-wide reconciliation additionally requires `student_enrollment_catalog` and `enrollment_reconciliation`. A missing migration displays an upgrade instruction.

Each browser profile generates a random UUID in extension-local storage. This is an installation identifier, not a hardware identifier or fingerprint. Browser/OS labels are coarse descriptive metadata; users can name the connection during pairing or rename it in EduLog. Same-installation pairing atomically replaces earlier tokens for that user and extension origin. Other installations and unidentified legacy tokens are preserved. Clearing extension storage or reinstalling creates a new installation identity.

Legacy adoption cannot supersede an already active known-installation authorization. It fails safely if another pairing has won; stale background verification does not overwrite newly saved pairing data. Reconnect from the current popup if a legacy credential cannot be adopted.

The web settings list refreshes every two seconds while a pairing request is pending/approved, every ten seconds otherwise, and immediately when the tab regains focus/visibility. Polling pauses in hidden tabs. Approval keeps the request visible until claim completes. Background refreshes retain rows and typed names; failures offer a manual refresh. Revocation requires confirmation showing the name and short connection ID.

Verification uses synthetic fixtures only. Run the isolated database test with `node supabase/tests/web_extension_installations.mjs <pglite/dist/index.js>`, or run `web_extension_installations.sql` against a disposable PostgreSQL database after applying the migrations. The web fixture is available at `/tests/fixtures/extension-connections.html` on a temporary Vite server at port 5199; `app/tests/extension-connections-browser.mjs <playwright/index.mjs> <screenshots-directory>` tests its layout and native dialog keyboard behavior in isolated Chrome/Edge profiles.

This directory contains the Manifest V3 Chrome and Edge extension source. Load it as an unpacked extension from `chrome://extensions` / `edge://extensions` while developing.

The extension connects to a self-hosted EduLog system. The user enters that server's origin and grants access only to that origin. Configure its `API_EXTENSION_ALLOWED_ORIGINS` with the exact `chrome-extension://<id>` origin before pairing. Production servers must use HTTPS; localhost is allowed for development.

Site-specific matching is isolated in `adapters/orange-apple.js`; the shared panel and connection flow use generic teaching-system terminology. The initial adapter is scoped to `corp.orangeapple.co` in both that adapter and the manifest's host match. Adding another teaching system means adding a separate adapter and its narrowly scoped manifest match.

UI improvements are enabled by default, independently of pairing or API availability. The adapter improves the teacher overview (`/`), class list (`/courses/dt`), class workspace (`/courses/dt/:id`), report grid (`/courses/dt/:id/lesson_reports`, including the dynamically loaded workspace tab), student learning history (`/dt_admissions/:id`), calendar (`/calendar`), and monthly unfilled list (`/admissions/month_unfilled_report`). The report edit modal has its own lifecycle, grouped fields, accessible labels and a keyboard-operable rating selector that updates the original radio inputs. Native forms, handlers, validation and submission remain in control. Unknown and access-denied pages retain their original UI. The toolbar and popup can switch improvements off; this preference is stored per adapter and synchronized across open supported pages.

Turbo navigation, frame updates and cache preparation restore/reapply the UI without cloning source forms. Search text is held only for the current page; only the UI enabled preference is saved. Styling is scoped to an opt-in document attribute and the shared toolbar has isolated styles. No teaching data is automatically exported.

Current-class import captures stable student/enrollment/report identifiers from known links and can read that class's report list and captured student-history paths. Select destination classroom/course/class and explicitly match students, enrollments, dated occurrences and reports. Same names never merge automatically. Missing IDs, full dates, schedules or course identities are marked for handling; the extension does not infer them. Reports with at least one verified teaching field can import even when comments are blank; unmapped materials/options and incomplete fields stay marked for handling. A reliable source report-edit URL is saved as the report link. Review differences before writing; conflicts keep EduLog unless explicitly selected. Batches use at most 50 records and the API's request-size limit, with atomic mappings/writes and replay-safe checkpoints. New students are grouped with a complete enrollment.

Report prefill is available both from the workspace and as an isolated panel inside a recognized native report editor. The panel first looks up the mapped student, enrollment and exact lesson date. A unique match opens a preview; otherwise, the teacher can search accessible reports as templates and explicitly confirm identity/date differences. Each native field is reviewed separately; existing values stay unchanged unless overwrite is confirmed, and internal notes require a separate opt-in. Applying rechecks the native form fingerprint and report version, writes selected values through native controls, and leaves submission to the teacher. The state remains **待人工送出／待確認**; no successful-submit observer or confirmation endpoint is enabled. All-visible-class collection, unknown form options, and confirmed submission remain release gates requiring reliable samples and live acceptance. Student detail pages (`/students/:id`) remain unsupported until an accessible sample is available.

Checkpoints and collected teaching data live in trusted extension IndexedDB, bound to instance/user, for at most seven days. Completed/cancelled import payloads and pending native-form payloads are cleared. Closing the popup or restarting the worker does not discard saved checkpoints. Changing instance/user or navigating the source stops mismatched work; already collected imports can resume after the source tab closes. Cancelling preserves committed batches. Retrying a pending-record write never reapplies or submits the source form.

Verification refreshes the frontend settings URL from `/api/extension/v1/me` for existing pairings. Configure `EDULOG_WEB_BASE_URL` on the API with the browser-visible frontend URL, including any port or path prefix. The API address is never used to guess the frontend address. See [workspace deployment and sample gates](../docs/deployment/extension-workspace.md).

Class cards and calendar status describe only the data currently loaded by the website. Source slot numbers are not converted into guessed clock times. The list/matrix choice, local filters, week selection and student expansion stay in page memory and are not uploaded or persisted in extension storage.

The popup displays setup, pending approval, connected overview, reconnect, or retry according to verification status. Temporary failures preserve credentials. Connected users can open integration settings, recheck, or change the server; cancelling server editing retains their current pairing. Diagnostic details and request IDs appear in a disclosure.

If the extension is reloaded while a teaching page is open, both synchronous and asynchronous context errors are caught. A single notice asks users to save edits before manually refreshing. Local UI switching and native forms remain usable; preference changes cannot be saved until the page is refreshed. Background failures allow retry without discarding pairing.

## Enrollment reconciliation (1000121)

Roster headers distinguish grade, course and registration date. Payment status is never mapped to enrollment status, and an expected course-start hint is not a registration date. Each source admission keeps its own student/course identity. Old grade-based snapshots require **補讀來源資料**; identity changes stop automatic reuse until reviewed. Remembered choices and existing EduLog data are retained.

**查詢既有報名** reads a selected student's accessible enrollments across classes and courses. Results show the class schedule, course, localized status, date, differences and an EduLog link. **重新核對此筆** refreshes current enrollment relationships and readable single-lesson transfer records. These reads do not infer permanent transfer history or decide which system is correct. Handle transfers in EduLog, return and recheck. No transfer mutation is exposed to the extension.

New enrollment requires a completed student-wide lookup and an explicit review checkbox; an existing exact match must be selected instead. **保留 EduLog 並略過此筆** preserves choices and excludes that admission and its reports from writing. Related records with unresolved identity, class/course or known transfer-target differences stay unimported. Capability flags `student_enrollment_catalog` and `enrollment_reconciliation` require 1000121; older servers offer upgrade guidance. Class labels include weekly/monthly/specific-date schedules, Sunday zero and short IDs.

Before previewing selected reports for existing enrollments, the workspace refreshes readable reconciliation records in bounded pages. A moved source occurrence, superseded target, missing date or failed check excludes the related report. No report is moved between occurrences. Schedule display supports multiple rules; class creation/import still follows the existing complete weekly-schedule write contract and does not infer monthly or specific-date writes.

## Import result verification and embedded prefill (1000122)

`PATCH /imports/:id {status: complete}` only updates the old job state and is no longer used by the extension to claim synchronization. The extension now checks every expected idempotent batch with `POST /imports/:id/complete`, reads its checkpoint/result summary through `GET /imports/:id`, and compares selected enrollments against EduLog's effective roster for the chosen local date. Results are separated by students, enrollments, occurrences and reports, with waiting, unchanged, skipped and failed data kept distinct. Unresolved mappings or roster differences remain visible as work to handle; they are not reported as a full sync.

Import snapshots include source reports only when they contain at least one verified teaching field. A reliable OrangeApple report-edit URL is stored as the report's `external_link`; existing content or a different link remains a conflict for explicit review. Effective-roster verification uses the configured class timezone and identifies missing/extra enrollments without deleting pre-existing EduLog records. Work history loads local IndexedDB and server-side records independently; a failed local database connection is reopened safely, while a failed history source offers its own retry.

Inside the native report editor, the isolated **EduLog 報告預覽** panel searches by remembered enrollment and complete lesson date. It opens a unique match for preview, or lets the teacher search reports as templates. Nonempty native fields are preserved unless each overwrite is checked; internal notes require separate confirmation. It validates the form fingerprint and report version before applying values through native controls. It never ticks the original confirmation box or submits the website form. ## One-time transfers and report imports (1000125)

An existing enrollment may be explicitly mapped to a source admission when the student and course match, even if its saved class session differs. This confirms only the source-to-enrollment identity: it does not change the enrollment's class, course, student, or schedule. The mapping remembers the enrollment's current relationship version and must be reviewed again if that relationship changes.

Reports for a different class session remain blocked unless the selected report date has a readable, effective, non-cancelled single-lesson transfer into the selected session and the enrollment is on that session's effective roster for that date. Cancelled, superseded, missing, date-mismatched, or inaccessible transfer evidence blocks the report. The import does not move the enrollment or create a duplicate enrollment for the transferred lesson. Older servers remain safe and block this case with an upgrade message.

Apply **1000125_extension_transferred_occurrence_import.sql** after 1000124, restart the API, update/reload the extension, and recheck the connection. The `transferred_occurrence_import` capability is available only when the new workspace migration is installed. Run `npm run test:extension-db --prefix server` for the isolated migration, permission, roster, transfer, idempotency and rollback checks. Actual Chrome/Edge sideloading, production RBAC and live transfer records remain separate acceptance steps; the website report is still submitted manually.

## Date questions and responsive report assistant (1000123)

The native report editor now keeps its own form on the left and the isolated EduLog assistant on the right at widths of at least 1200px (56/44, dialog max 1440px). Narrower windows switch between the existing panes without replacing controls, events or drafts. The native close control and source target summary remain visible. Collapsing the assistant restores the original layout.

Strict calendar parsing accepts full ISO/slash/dot/Chinese dates and partial month/day values. A missing year is resolved only from unique reliable source evidence or matching report-ID history. Otherwise the teacher confirms the full lesson date. Conflicting source evidence requires explicit acknowledgement. Temporary date and enrollment answers are marked **使用者確認**, survive reopening the same report with unchanged evidence in the current document, and never create permanent identity mappings or modify the source website. Enrollment answers are bound to the paired instance and user. Refreshing the source clears these document-local answers.

Candidate groups distinguish exact-day matches, the same student's same-course reports across enrollments, and other courses. Fallback same-course reports load automatically when the exact group is empty; other courses load on expansion. The server orders by distance to the target day before paging (50 maximum), with past dates first for ties and stable IDs last. Scoped cursors, readable class/material labels and signed day offsets require **1000123** and `nearest_report_candidates`. Without a confirmed target day the assistant explicitly sorts from today in the source timezone. Selecting another day or enrollment is template use requiring confirmation.

Reviews group attendance, progress, ratings, feedback/contact and internal notes. Native nonempty values require per-field overwrite consent; internal notes require separate consent. Completion false is never matched to completed, missing values remain missing, and rich text is converted to plain paragraphs. Apply rechecks the native fingerprint, date, current target and report version, reports actual field outcomes, and never ticks the source confirmation checkbox or submits the form. Rechecks preserve selected-report drafts and focus/caret; late responses cannot overwrite a newer selection.
