# 本輪待重新確認清單與連續處理驗收

## 行為

- 「本輪待重新確認」依 `staleReviewPending` 建立，與一般報告分類分離；只顯示本輪仍待確認的報告，不混入其他報名、系統排除或一般待處理項目。
- 從同步摘要開始或前往核對會切換至歷史核對區並套用本輪分類。若目前搜尋會隱藏目標，清除該搜尋後再定位；原因篩選不會漏掉待確認報告。
- 左側清單、頂部剩餘報告／欄位數及下一份導航使用同一份待確認集合與順序。搜尋只改變「符合搜尋」及下一份範圍，不改變本輪總數。
- 桌面將焦點移至右側待確認控制並把學生／報告列捲入左側可視範圍；手機切換至編輯畫面。一般統計及普通下一項操作在核對模式收起。
- 保存中的欄位仍計入待確認數；只有本機草稿保存成功後才暫留目前列並標示「決定已保存，待更新差異」。離開該列後它即移出清單。保存失敗時恢復待確認標記及原選擇。
- 下一份依目前搜尋往前移動。搜尋內已無下一份但本輪仍有其他項目時，提供清除搜尋操作。完成後明示已保存但尚未同步，必須返回摘要更新差異，再由使用者確認同步。
- 返回摘要還原之前的分類、搜尋、原因篩選、選取、捲動及展開狀態；工作切換後舊工作回應不會改動新清單。

## 自動驗收

- `history-workbench.test.mjs` 驗證集合來源、排除一般分類、搜尋範圍、保存期間計數、成功暫留與失敗還原。
- `workspace-preview.test.mjs` 驗證 18 份／32 欄位摘要、階段與報告分頁切換、待確認導航及同步門檻。
- `history-browser-check.mjs` 使用實際工作台 DOM 與樣式，在 Chrome／Edge 的 360、390、768、1024、1200、1440、1920px 及 1440×480 合成視窗檢查清單、搜尋、下一份、焦點、捲動及水平溢位。
- 自動化不連接真實網站、不使用真實學生資料、不提交教學紀錄。合成瀏覽器結果與真實側載驗收分開記錄。
