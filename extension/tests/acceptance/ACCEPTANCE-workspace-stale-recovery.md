# EduLog 0.1.0：工作恢復摘要例外修復

## 查證與修正

- 附件顯示「正在恢復所選工作」階段的 `WORK_FAILED`，但沒有留下原始例外訊息，無法只憑附件確認該次事件的唯一原因。
- 現行 `staleReasonLabel` 使用未宣告的 `t`。移除測試額外注入的 `t` 後，重現 `ReferenceError: t is not defined`。恢復舊工作並重新繪製失效摘要會經過這個函式。
- 改為函式內使用既有翻譯服務；沒有翻譯服務時提供繁中備援。移除重複、無法到達的分支。
- 介面程式例外使用 `WORKSPACE_UI_ERROR`，與 API／版本衝突分開呈現。診斷只保留例外類型、白名單 JavaScript 訊息及檔名行號，不複製任意訊息或完整 stack。
- 發生介面例外即撤銷目前摘要的同步資格，提供「重新開啟並核對工作」。重試依既有來源、工作 ID 與批次恢復，先讀取伺服器檢查點後再預覽；不建立新匯入、不自動寫入教學資料。
- 其他預覽錯誤呈現本次實際錯誤訊息，不再被舊的通用失敗提示蓋住。成功重試會隱藏該次錯誤與診斷。

## 驗收結果

- 擴充功能全套：313 項通過，0 失敗。
- 原始模組函式測試不注入全域 `t`，驗證舊診斷採中性提示、可信診斷呈現已確認原因；繁中／英文訊息均存在。
- 安全診斷測試驗證不洩漏任意例外中的報告正文或憑證。
- Chrome／Edge 合成工作台使用未改寫的原始 ES 模組與實際本機分段草稿儲存，僅追加測試存取器，全部外部回應為合成資料。
- 390×900 手機及 1440×480 短視窗各通過：恢復舊／可信失效診斷、重新繪製摘要、可見性、原工作與批次鍵保留、介面例外顯示、同步停用、鍵盤重試、成功後清除錯誤、無頁面橫向溢位及至少 44px 操作範圍。
- 每個瀏覽器情境均捕捉未處理例外、Promise 拒絕及畫面中的被捕捉錯誤；最後明確同步前，教學資料寫入與新建匯入請求數皆為 0。
- 封裝檢查 manifest 入口、模組依賴及包內全部 JavaScript 語法；核對包內更新腳本與來源一致。
