# EduLog 0.1.0：預覽失效誤報與精準恢復

## 修正內容

- Migration `1000137` 讓失效診斷使用與預覽／提交相同的目標版本值：不存在為 `new`；存在時優先使用資料版本，否則使用目標 JSON 的 MD5。診斷逐列檢查，因此不會把較早但未變的學生誤報成衝突列。
- 歷史報告與課次報告版本分別核對。只有具讀取權限且可安全定位時才回傳種類、來源識別、欄位與原因；無法確認時保留通用 `PREVIEW_STALE`。
- 恢復會先讀伺服器批次檢查點，再沿用原工作、批次鍵及內容重查未提交批次。檢查點不一致時停止並要求查看結果，不自動提交。

## 自動驗收

- PGlite 使用去識別化 50 列學生批次：前 49 列保持未變，第 50 列在預覽後變更；診斷指向第 50 列，並驗證同批次重預覽後可提交。
- PGlite 工作區完整 migration 回歸通過，包含預覽指紋、版本失效、歷史／課次核對、權限及交易回滾。
- 擴充功能測試新增恢復檢查點情境：恢復先查匯入檢查點，再重查原批次；確認期間沒有 `apply` 請求。另驗證本機與伺服器檢查點不一致時不重查、不寫入。
- 擴充功能全套測試：**277 項通過**。
- API 全套測試：**235 項通過**；伺服器 TypeScript 型別檢查通過。
- Chrome／Edge 合成瀏覽器：工作台恢復、分段草稿及 360–1920px 版面檢查通過，使用 mock API。
- 側載封裝檢查 staging 中所有 JavaScript 語法、manifest 入口及相依檔，並確認包含 `1000137` 與本驗收文件。
