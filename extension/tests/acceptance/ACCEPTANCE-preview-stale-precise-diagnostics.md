# EduLog 0.1.0：同步失效診斷與精準恢復

## 修正

- 新增 migration `1000139`，在預覽指紋、一般目標版本及歷史／課次報告版本的實際檢查點附上受限診斷；失敗回滾後不再重新掃描並推定衝突列。
- 新增歷史關係依請求中的報名與課次查詢課次報告，不依賴尚未建立的歷史列。
- API 僅公開帶有 `diagnostic_source: version_check` 的白名單原因與請求內識別。舊資料庫診斷維持中性 `PREVIEW_STALE`。伺服器日誌記錄工作、批次、操作、原因及版本，不記錄正文或憑證。
- 工作台只對可信診斷顯示具體原因；舊草稿／舊伺服器診斷顯示「預覽已失效，原因尚未確認」。恢復仍先讀伺服器檢查點，沿用原工作、批次鍵與成功檢查點，不會自動套用。

## 自動驗收

- PGlite 完整 migration 回歸包含兩列歷史混合批次：前列新增歷史的課次版本不變，後列既有課次報告版本改變；回應定位後列，且失敗交易回滾前列新增資料。
- API 回歸驗證可信診斷才會附上 `diagnostic_source` 與欄位；舊診斷及不安全識別回傳中性錯誤。
- 擴充功能回歸驗證可信診斷傳遞至工作台而不傳遞版本值，且不把舊診斷誤標為已確認的版本衝突。
- 本次驗收：API 全套 235 項通過；擴充功能全套 312 項通過；資料庫完整 migration 回歸通過；伺服器 TypeScript 檢查通過。
- 封裝腳本已檢查 manifest 入口、包內依賴及所有 JavaScript 語法，並確認版本仍為 `0.1.0`。
- 側載包已產出並檢視 ZIP 內容；包含 migration `1000139`、本驗收文件及工作台更新腳本。

## 待驗收

- 使用者提供的實際工作未重放；該次 `PREVIEW_STALE` 的唯一失效原因仍未確認。實站僅讀取，沒有提交教學資料。
- 真實 Chrome／Edge 側載、瀏覽器背景服務重啟及跨裝置恢復尚未實測。合成測試結果與實際側載分開記錄，這些項目仍待驗收。

- 版本維持 `0.1.0`；沿用端點及舊草稿格式。
- 側載包：`extension/dist/EduLog-Teaching-Tools-0.1.0-preview-stale-precise-diagnostics.zip`。封裝不會執行資料庫 migration。
