# EduLog 0.1.0：歷史列分類與有效報告核對

本輪先分類 corp 歷史表格中的來源列，再建立同步核對項目。沿用既有 API 與資料庫，不新增 migration；原站教學表單仍由老師人工送出。

## 已驗證

- 自動測試使用去識別化 DOM 與合成紀錄，驗證 `前一報名` 必須以原生報告連結讀取前一報名，並以可靠學生 ID 及課程代碼確認歸屬；無法確認的列分類為其他報名，不進入同步 payload。
- 編輯連結中的來源報告 ID 與「設為不出席」URL 的查找 ID 分開保存。查找 URL 不會被執行；實際出席狀態只從列上保存內容或原生編輯表單擷取。
- `colspan`／`rowspan` 會先展開為邏輯欄位，再按表頭辨認日期、堂次、出席及評估欄。
- 空白的「設為不出席」列分類為尚未填寫；有已保存出席或教學內容的列保持為報告。明確假日且沒有教學內容會系統排除。日期不會單獨排除有內容的報告。
- 前一報名報告的本機來源報名可獨立映射至原課程。讀取其編輯表單時，工作代理只接受來源頁證據匹配且歸屬已驗證的紀錄；局部重試回到原始歷史頁。
- 自動排除在摘要分組呈現，計數和原因可供篩選；這些列不顯示逐筆映射或略過操作，也不計入待處理報告數。
- 全套擴充功能自動測試：**238 項通過，0 項失敗**。包含來源擷取、同步分類、工作台及代理讀取權限回歸。

## 尚待實站驗收

尚未以 Chrome／Edge 真實側載讀取 corp 頁面。本輪沒有提交教學資料。需在更新前保存原站草稿，重新載入擴充功能與來源分頁，再檢查跨欄列、跨報名連結及待填按鈕列的實際 DOM 是否符合合成樣本。
